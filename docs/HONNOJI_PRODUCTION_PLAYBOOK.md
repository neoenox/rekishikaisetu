## 1. 題材の調査と台本づくり

**台本の編集元は `scripts/hn_story.py` 1か所。** 場面を、`(キー, 画面タイトル, 小見出し, 出典ID, ナレーション)` で並べ、`ORDER` で順序を決める。実行すると `data/hn_scenes.json`（台本）・`data/hn_sources.json`（出典）・`data/hn_pronunciations.json`（読み辞書）を書き出す。

### 1-1. 構成の決め方（この動画での実績）
1. 冒頭：数字の落差と問い（約20秒）。**断り書きは1文以内。**
2. 経緯（人物→春→五月→当夜）。
3. 当夜の行軍（3D地形・道路に沿った経路）。
4. 事件（本能寺・二条）。
5. その頃、各地では（地図で人物の動きを見せる）。
6. 史料を読む（書かれた時期で分ける）。
7. 諸説を比べる（骨子→論者→根拠→反論→いまの位置、の同じカード）。
8. まとめ（冒頭の問いに答えを返す）。
- **他の戦い・事件は、別の動画に回す**（この動画では、1文触れるだけ）。
- 豆知識（`tr_*`）は、物語の山場の直前・直後に挟まず、1か所にまとめる。

### 1-2. 事実の確認（最重要）
- **調べる先：日本語版Wikipediaの該当記事**（WebFetchで、「記事にある範囲で」と指定し、「記述なし」と答えさせる）。長い記事は途中で切れるので、`offset` を指定して続きを読む。座標は国土地理院の住所検索API（`msearch.gsi.go.jp`）。
- **確認できないことは、台本に入れない。** 例：「堀や土塁のある城のような寺」「家忠日記の誤報」「家中軍法の条文」は、確認できず、除いた。
- **資料同士が食い違うときは、幅のある表現にする**（渡海予定日：6/2説と6/3説→「六月の初め」）。
- **現在形の評価（「現在も支持」「有力視」）は、本人の近年の見解が確認できないので、「支持する論者として知られる」「注目を集めた」に弱める。**
- 研究者名を画面に出すときは、**誰が提唱・評価・批判したかの取り違え**を、特に確認する。

### 1-3. 文章の規則（音声合成のため）
- 1文は50字以内、「。」で終える。**数字は漢数字**で書く（読み間違いが少ない）。字幕は、`scripts/hn_text.py` の `display()` で算用数字に変換（年・日付・人数・距離など）。
- **ナレーションに、制作の言い訳を入れない**（「画面は〜」「この地図では〜」「〜は仮置き」「〜とは照合しない」）。歴史の内容としての留保（「諸説」「とされる」「確かな史料とはいえない」）だけ残す。制作側の注記は、画面の小さな注記か概要欄へ。
- 難語は、やさしい言葉に言い換える（「与力→配下に付けられた」「参籠→泊まり込んで祈り」）。

### 1-4. 読み辞書
`hn_story.py` の `PR` に、エンジンが誤読する語だけを足す（長い語から先に置換されるので、「小和田哲男」と「小和田」の両方）。**足したあとは、必ず次の読み確認で効果を見る**（逆に壊れる語がある：信憑性）。

## 2. ★ 台本のクロスチェック（Claudeが書き、ChatGPTが評価）

1. 評価依頼文を作る（`out/chatgpt_review_prompt_30min.md` の形式）：動画の前提、評価の観点A〜E（事実／諸説の公平さ／聞きやすさ／視聴維持／抜けている文脈）、**「書き直さない・新事実には出典を付ける」**、出力形式（総評・指摘の表・問題なしの主張・自信の低い判断）、台本全文。
2. ★ 人が、ChatGPTに貼り、返ってきた評価を会話に貼る。
3. **指摘を1件ずつ、資料で確認する**（評価者も間違える）。判定は「採用／一部採用／変更なし／保留」と理由を記録（`out/script_crosscheck_log.md`）。**確認できない出典名（博物館の解説・書籍名）は、根拠にしない**。確認できないときは、表現を弱める（安全側）。
4. 採用分だけ、台本を直す。**評価待ちの間は、音声・映像を作り直さない**（台本の変更で全場面のタイミングが変わるため）。
5. 評価が「BLOCKER」を出したときの解除条件を、記録する（今回：原著・一次史料での確認が未実施のため、**投稿前に、研究者名つきの学説紹介を、原著で確認するか、さらに弱める**）。

## 3. 地形・写真・経路のデータ

```powershell
.venv\Scripts\python.exe scripts\hn_terrain.py     # DEM z14 → data\hn_terrain.npz（30mメッシュ）＋ cache\hn_tiles
.venv\Scripts\python.exe scripts\hn_texture.py     # オルソ(ort) z15の基底(6m/px)＋中心部z17パッチ(1.2m/px) → cache\hn_texture.png, hn_patch.png
.venv\Scripts\python.exe scripts\hn_roads.py       # 道路データ(ベクトルタイル) → cache\hn_roads.json
cd scripts; ..\.venv\Scripts\python.exe hn_route.py          # 最短経路 → cache\hn_route_raw.npz
..\.venv\Scripts\python.exe hn_analyze_road.py; cd ..         # 距離・登り下り・所要時間 → data\hn_analysis.json, hn_places.json
```

- **DEM**：国土地理院 `dem_png` z14、欠損があれば停止（穴埋めしない）。高さは**2倍に強調**して描く（画面に明記）。数値（距離・登り下り）は強調前のDEMから。
- **写真は `ort`**（最新オルソ）。`seamlessphoto` は、撮影時期の違う範囲が、明るい四角いパッチとして残る。
- **中心部だけ高解像度**：z17を、縁を透明にぼかしたRGBAにして、別メッシュ（10m格子、1.2m浮かせる）に貼る。
- **経路は、現代の道路網に沿わせる**（直線で結ぶと、距離・標高が実態と違う）。国土地理院の最適化ベクトルタイル（`experimental_bvmap` の `road` レイヤー、z15）を、`hn_roads.py` の最小MVTパーサーで読み、頂点をグラフにして、`scipy` のダイクストラで最短経路。コスト＝長さ×道の種別×（1＋勾配の超過ペナルティ）。**トンネル（地形が両端より12m以上高い辺）は除外**（現代の老ノ坂トンネルを通ると、旧道の峠越えにならない）。経路の限界（現代の道路・当時の街道とは限らない・桂川は現代の橋）は、画面・台本・出典表に書く。
- **経路を変えたら、距離・登り下り・所要時間の数字が、台本（漢数字）・画面のパネル・グラフ・概要欄・出典表の全部で変わる。** 数字を一覧にして、全部更新する。

## 4. 読みの確認と音声合成

```powershell
$env:PYTHONIOENCODING='utf8'
.venv\Scripts\python.exe scripts\hn_story.py          # 台本を書き出す
.venv\Scripts\python.exe scripts\hn_kana_check.py     # ★ 全文の実際の読み → out\hn_kana.txt（目視で確認）
.venv\Scripts\python.exe scripts\hn_audio.py          # 音声・字幕・タイムライン
```

- **読みの確認は、合成の前に必ず行う。** VOICEVOXの `/audio_query` が返す `kana` を全文出力し、人（または私）が目で見る。誤りは辞書へ（過去：大坂→ダイサカ、三河→ソウゴ、上野→ウエノ、小和田→コワダ）。約270文で約5分。
- 音声は、四国めたん「ノーマル」、**話速 `SPEED=0.95`**（1.0は「早い」、0.88は「ゆっくりすぎ」と評価された）、抑揚1.08、文末の無音 +0.35秒、場面末の余白 1.6秒。**場面の長さは、WAVの実サンプル数から決める**（手入力の秒数で同期させない）。
- `hn_audio.py` は、**`hook_end`（冒頭の引きの終了秒＝先頭場面の3文目の終わり）を、タイムラインに自動で書く**（2026-10-15に組み込み。以前は手で追記していた）。字幕（`out/hn_subtitles.srt`）は、`hn_text.display()` で算用数字に変換して書く（ナレーションの元の文は、漢数字のまま）。
- 生成直後の音量は約 -24.6 LUFS（最終工程で -15 LUFS に正規化）。

## 5. 素材

### 5-1. 肖像・錦絵（`scripts/hn_portraits.py`）
Wikimedia Commonsの**パブリックドメイン表示**の画像のみ。APIで説明ページ（所蔵・作者・年代・PD表示）を取得して記録。サムネイルURLは、**許可サイズ（500・960・1280・1920px）**のみ（それ以外は400）。回数制限（429）は、間隔を空け、User-Agentを明示。直リンクは、曲・画像のページをRefererにしないと403のことがある。**別人の画像で代用しない。**

### 5-2. 位置図の下地（`scripts/hn_map.py`）
国土地理院の陰影起伏図 `hillshademap` を、暗色に加工（日本全体z9・広域z8・近畿z11・中京z9・岡山z10・東日本z9）。**下地は、対象より十分広く取る**（小さいと、拡大率の下限で、ピンがパネルの下に隠れる）。

### 5-3. 兵・炎・煙
- 兵：既存の関節付き隊列のスプライト生成（`render_army_sprites.py`）の色違い（`hn_sprites.py` → `assets/army_hn/`）。
- 炎・煙：`hn_fx.py`（手続き生成のPNG → `assets/fx_hn/`）。

### 5-4. BGM（魔王魂のフリー音源）
- 規約：「音楽：魔王魂」の表記（概要欄で可）。**★ ダウンロードは、曲名・URL・出典を示して、人の許可を得てから行う。** 直リンクはRefererなしで403 → 曲ページをRefererに付ける。取得後、`ffprobe` で音声か確認（403のHTMLがmp3として保存されることがある）。保存先 `assets/bgm_maou/`。
- 曲の割り当て：`scripts/hn_bgm_maou.py` の `PLAN`（開始場面キー・終了場面キー・曲）。曲ごとに -24 LUFSへ揃え、場面の境目は3秒の等電力クロスフェード、曲より長い場面は、継ぎ目をクロスフェードで繰り返す。**私は音を聴けない**ので、曲の相性は、人が聴いて判断する。
- 自作の合成BGM（`hn_bgm.py`）も残している（権利不要。外部曲が不要なら、こちら）。

### 5-5. ★ イメージ画像（ChatGPT生成、任意）
- 依頼文：`out/image_prompt_kit.md`（共通の指示＋場面ごと12点）。**画風は錦絵風、実在の人物の顔・文字・流血を禁止、時代・季節の具体指定**（「紅葉は描かない」「天守は描かない」）。
- ★ 人が生成して、画像を渡す。私が時代考証を確認（`out/image_review.md`）し、使用可否を決める。保存先 `assets/imagen/`。
- 画面に「イメージ（生成画像・史実の再現ではありません）」を常時表示、概要欄にも明記。★ 利用条件・YouTubeの「改変または合成されたコンテンツ」の開示は、投稿者が確認。

## 6. 画面の設計（JSON。ここを編集すれば絵が変わる）

### `data/hn_scene_visuals.json`（場面キーごと）
| キー | 意味 |
|---|---|
| `date` | ヘッダー右の日付 |
| `map` | 位置図の場面。`base`（下地）、`items`（`pin`・`arrow`・`path`）、`panel`（年表：[文,出現する文の番号]）、`cards`（肖像） |
| `trivia` | 豆知識の場面。`bg`（背景に使う3D場面のキー）、`headline`、`lines` |
| `theory` | 史料・諸説のカード。`tag`、`name`、`rows`＝[ラベル,本文,出現する文の番号]。行数・文字数で、フォントを40→34pxに自動切替 |
| `images` | `[[画像名,開始文番号,終了文番号]]`。該当する文の間だけ、全面で表示 |
| `cards` | 肖像・錦絵のカード（[画像,[x,y,幅],出現する文の番号]） |

- **出現のタイミングは「ナレーションの文の番号」で指定**（秒数を直書きしない）。台本・音声が変わっても、追従する。
- **画像・年表の出現が、その文に連動する要素（経路のアニメーション等）と重ならない文を選ぶ。**
- 場面を入れ替えたとき、画面タイトルの番号は、`disp_title()` が、表示時に振り直す（台本に番号を直書きしない）。

### `data/hn_cameras.json`
場面キー → 3Dカメラ（`target`・`dist`・`elev`・`az`・`army`・`marks`・`army_on`・`siege`・`fire`・`dawn`・`compound`）。位置図は `{"kind":"map"}`、豆知識・諸説は `{"kind":"trivia"}`（**3Dを描かない**）。

### 画面の規則
- 文字は30px以上。上下の帯は使わず、縁取りの文字と上端の薄い影で読ませる。見出し＝Noto Serif JP、本文・字幕＝Noto Sans JP（可変フォント、`set_variation_by_axes`）。
- **動きを止める**：地図の場面は、ズームしない（整数座標に丸められる描画と、滑らかな背景を組み合わせると、ピンが階段状に動く）。ラベルは、場面ごとに位置を1回決めて固定（`stable_slot`）、ピン・矢印・文字は、2倍の大きさのレイヤーに描いて、箱形フィルタで縮小。
- 制作の注記は、右上に1行（「高さ2倍強調｜現代の地形・写真｜軍勢は模式表現」）。出典・クレジットは、動画内に入れず、概要欄へ。

## 7. 3D描画（Blender）

```powershell
# 全フレームを、2プロセスで（GPU使用率が上限なので、増やしても速くならない）
$b='tools\blender-4.5.3-windows-x64\blender.exe'
& $b -b -t 6 --python scripts\hn_render.py -- main 0 <N/2>
& $b -b -t 6 --python scripts\hn_render.py -- main <N/2> <N>
```
- **確認用**：`-- bench`（各3D場面の中央の1枚、50%解像度、数秒）、`-- test 100,300,…`（指定フレームのみ）。**本番の前に、必ず見る。**
- **3Dが必要なフレームだけ描く**（位置図・豆知識・諸説・冒頭の引きは描かない：`is3d()`）。既存のJPEGは、再開時に飛ばす。強制終了時に壊れた1枚が残るので、再開後に**全JPEGをデコード検査**し、壊れた分だけ消して再描画。飛ばしたフレームの計測値は、`HN_META=1` を付けて、**描画せずに**再計算。
- 環境変数：`HN_OUT`（出力フォルダ）、`HN_KEYS`（描く場面キー）、`HN_META`。経路を直した場面だけの再描画は `HN_OUT=hn_v4 HN_KEYS=d_depart,d_oi,d_katsura,d_time`、そのときの旧タイムラインを `data/hn_timeline_v4.json` に保存（合成側が、場面内の進み具合で対応づける）。
- 描画の仕様：Eevee、メートル単位のDEM（高さ2倍）、オルソ画像、軍勢・炎・煙は、カメラを向く板ポリ（ビルボード）にスプライト。暗い場面（未明）では、スプライトを弱い発光にも接続（真っ黒を避ける）。炎の幅は寺地（120m）の半分程度。
- **描画済みの3Dの再利用**：カメラ・軍勢の動きは、「場面内の進み具合（0〜1）」だけで決まる。台本・音声が変わって、場面の長さが変わっても、`hn_compose4.py` の `old_frame()` が、同じ進み具合の、描画済みフレームを探して、**前後2枚を補間**する。場面の構成（カメラの動き）を変えたとき、長さが半分以下になったときは、再描画が必要。

## 8. 合成と仕上げ

```powershell
Remove-Item cache\hn4_part_* -ErrorAction SilentlyContinue
# 全フレームを、6並列（約9000フレームずつ）
foreach($r in '0 9000','9000 18000','18000 27000','27000 36000','36000 45000','45000 54000'){ $a=$r.Split(' '); Start-Process .venv\Scripts\python.exe -ArgumentList "scripts\hn_compose4.py part $($a[0]) $($a[1])" -RedirectStandardOutput logs\c4_$($a[0]).log -NoNewWindow }
# 6個の断片（cache\hn4_part_*.json）がそろったら
.venv\Scripts\python.exe scripts\hn_compose4.py final                  # 結合＋音量正規化（BGMなし）
Move-Item out\honnoji.mp4 out\honnoji_nobgm.mp4 -Force
.venv\Scripts\python.exe scripts\hn_bgm_maou.py                        # BGMの生成（場面の長さに追従）
.venv\Scripts\python.exe scripts\hn_compose4.py remix -6 hn_bgm_maou.wav   # BGMを載せて -15 LUFS、映像は再エンコードしない
```
- 断片の範囲は、総フレーム数（`round(timeline[-1]['end']*30)`）を、6等分。**合成前に、古い断片とJSONを削除する**（残っていると、結合が壊れる：`moov atom not found`）。完了の判定は、断片のJSON6個、または `ffmpeg.exe` の終了。
- **セッションが切り替わると、バックグラウンドのPythonが止まる**（パイプが壊れる）。進捗ログが止まっていたら、`taskkill` して、全断片をやり直す。
- 時間の目安（RTX 4060）：合成は、1フレーム約0.1〜0.2秒/プロセス。2倍サイズのオーバーレイを使うので、箱形フィルタで縮小（`LANCZOS` は2倍遅い）。
- BGMの音量：声との差が、話している間15〜20dB、間のBGMとの振れ幅10dB前後が目安（`-6`dB、`sidechaincompress` 比4・しきい値0.02・解放0.9秒）。**最終は人が聴いて決める**（`remix` の数値を変えるだけで、約1分で作り直せる）。
- 字幕：`out/hn_subtitles.srt`（音声の工程で生成済み。算用数字に変換済み）。

## 追補(2026-10-15)：外部レビューを受けた改訂(第2版)

### A. 動画の末尾が切れていた不具合(重大)
- 症状：動画は30:00で終わるのに、字幕(SRT)は30:14まで続いていた。最後のナレーションと結びが画面に出ていなかった。
- 原因：合成(`hn_compose4.py part A B`)を、**固定の範囲(…〜54000)で起動**していた。音声を作り直してタイムラインが延びた(54,478フレーム)のに、範囲を直さなかった。
- 対策：①範囲は `N=round(timeline[-1]['end']*30)` から計算し、最後の範囲が N 以上になるようにする(現行は 9200フレームごとの6分割、最後は 46000〜55200)。②`final()` の最後で `chk_duration()` が、**動画の長さとタイムライン末尾の差が1秒以内**であることを assert する。③投稿前の確認項目に「字幕の最終時刻＝動画の長さ」を加える。

### B. 構成の変更(諸説を、史料より前へ)
- 順序：…→その頃、各地では(第5部)→豆知識2本→**諸説(第6部)**→**史料(第7部)**→豆知識2本→諸説を並べて(まとめ)→結び。動機の比較が約16分から始まる。
- 諸説の見せ方：主張／根拠／弱点の3行を固定の位置に置き、いま読んでいる行に金色の枠。論者名は小さい注記(1行)にして、見出しには出さない。
