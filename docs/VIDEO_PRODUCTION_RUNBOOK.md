# 歴史解説動画の制作ノウハウ・再実行手順

更新日：2026-10-13。関ヶ原の試作で実際に動かし、動画まで出力できた手順を記録する。

この文書はプロジェクト内の引き継ぎ先。動画の制作結果は `out/EARTH_REPORT.md`、機械検証の実測値は `out/earth_quality_report.json` を参照する。機械的な検査通過と、史実の正確性・作品の完成度を分けて扱う。

投稿前の具体的な改善点と優先順位は [YouTube品質レビュー](YOUTUBE_QUALITY_REVIEW.md) に記録している。

## まず再生成する

既存の環境・取得済み背景を使う場合：

```powershell
cd E:\rekishikaisetu
pwsh -File scripts/run_earth.ps1 -ReuseCaptures
```

Google Earthの画面取得からやり直す場合：

```powershell
pwsh -File scripts/run_earth.ps1
```

どちらも完成MP4を上書きする。比較したい旧版は先に別名で保存する。`-ReuseCaptures` は背景の再取得を省く指定であり、完全オフライン実行ではない。現状の肖像取得処理は外部へ再アクセスする。

初回の環境導入は `scripts/setup.ps1`。既存環境では不用意に再導入せず、`scripts/doctor.py` とREADMEで確認する。公開・有料契約・GitHubへの送信はこの手順に含まれない。

主な出力：

|---|---|
| `out/sekigahara_google_earth_portraits.mp4` | 現在の本編。約3分44秒 |
| `out/earth_portrait_march_preview.mp4` | 進軍部分。約23秒 |

## 現在採用している構成と理由

Google Earthの実際の表示画像に、独自の軍勢と肖像を合成する。地形説明にはGoogle Earthの斜め3D表示、位置を追う進軍場面には俯瞰画像を使う。

最初のDEM版は実測の起伏を使っていても、地表の色と手続き的な森林が人工的に見えた。実景を伝えるには標高だけでなく森林・田畑・市街地の見え方が必要だったため、背景を変更した。以前のDEM版と品質1・2・3の比較動画は残している。

軍勢はBlenderで作った関節付きモデルを透過画像へ描画し、背景へ2D合成する。Googleの3Dモデルを抽出する方式ではない。写真だけの動かないサンプルでもなく、部隊の位置・歩行姿勢・肖像をフレームごとに描画する。一方、背景は取得済みの静止画像であり、連続したGoogle Earthフライスルーではない。

日本語音声はローカルのVOICEVOX、字幕と映像の合成はPython/Pillow、動画化はFFmpeg/NVENC。従来DEM版の見出し素材にはRemotionも使っているが、現在の帯なし版はPillowで直接文字を描く。

## 見せ方で得た判断

- 見出し50px、部隊名38px、字幕46pxを1080p画面の基準にする。小さい凡例・注記を増やすより、画面内の情報量を減らす。
- 上下いっぱいの濃い帯は地形を隠す。現在は見出しと字幕を地図に直接重ね、黒い縁取りを付ける。
- 役割が違う表示を重ねすぎない。部隊名の札、肖像、説明パネル、字幕は領域を分ける。字幕は最大2行。
- 人物の説明時は大きな肖像、進軍時は円形の肖像を使う。顔が動くと、誰の軍勢か追いやすい。
- 肖像は軍勢の真上へ固定するだけでは衝突する。指示線で結び、軍勢から横へずらし、字幕へ入らないよう縦位置を制限する。
- 画像の所蔵先・制作ソフトなどの詳しいクレジットは概要欄へ移す。Googleなど映像内の帰属表示を求める素材は例外として、小さく常時表示する。

これらは今回のユーザーの評価を受けたプロジェクト上の判断。万人に読みやすいことを測定した結果ではない。

## 台本・音声・字幕の同期

編集元は `data/earth_scenes.json`。音声生成は `scripts/audio.py earth`、その音声実長から `data/earth_timeline.json` を作る。

1. 出典を付した台本を確定する。史実参照・推定・仮説・演出を混同しない。
2. `data/pronunciations.json` で人物名・地名の読みを指定する。長い語から置換する。
3. 文単位で音声を生成する。本文・話速・話者のハッシュが同じ文は音声キャッシュを再利用する。
4. WAVの実サンプル数から尺を求め、シーン末尾に1秒の間を置く。30fpsのフレーム境界へ切り上げる。
5. 同じ区間情報から字幕と映像を作る。別々に手入力した秒数で同期させない。

`out/earth_audio_report.json` は生成結果で、台本の編集元ではない。音声を生成するにはVOICEVOXが必要だが、`run_earth.ps1` が起動・終了を管理する。既に別用途で動いていたエンジンを勝手に終了しない。

現在は制作クレジット専用の末尾シーンを外している。音声もそのシーンを除き、概要欄へ移した。再び付け足さないこと。

## Google Earth画像の取得

関係する処理は `scripts/capture_earth.mjs` と `scripts/capture_earth_views.mjs`。

- 実際のWeb画面をPlaywright/Chromiumで開く。画像タイルの一括取得や3Dモデル抽出はしない。
- 1920×1080、英語表示、既定のカメラURLを使う。俯瞰・広域・斜め視点を別々に取得する。
- 必要に応じてFlutterの「Enable accessibility」を有効にし、画面の名称・座標・読み込み状態を読む。
- Basemap設定をCleanにして、道路の記号や施設名を抑える。説明用の軍勢を見やすくするため。
- Data attributionを開き、実際に表示された提供元と画像日付を保存する。背景ごとに提供元が異なるので、一律「Airbus」にはしない。
- 表示された画像、帰属表示の画面、取得URL・日時を `assets/earth` に保存する。

初期取得で読み込み途中の広域画像が出た。待機時間だけで完成と決めず、読み込み100%を確認する。現在の待機ループにも上限があり、上限到達だけでは100%を保証しない。未完了なら採用せず、再取得する。

Google Earthの現代画像はライブ画像ではない。今回の画像日付にも2023年などの表示と日付不明部分が含まれる。Google Earthで現在公開されていることと、現在時刻の景観であることを区別する。

UI上の一部操作は画面位置に依存する。表示サイズ・Google EarthのUI・ブラウザーが変われば、そのまま動くとは限らない。

## 背景と軍勢を座標で合わせる

`scripts/register_earth.py` と `scripts/compose_earth.py` を参照。

1. 俯瞰画面の9地点へカーソルを移動し、画面に出た緯度・経度・標高を取得する。
2. WGS84の緯度・経度・標高を地球中心座標へ変換し、中心地点の東・北・上方向へ変換する。
3. 6地点で俯瞰カメラの投影式を合わせる。
4. 計算に使わなかった3地点でずれを測る。合わせた点だけで合格にしない。
5. 軍勢の陣跡座標と、別途取得したDEMの標高を同じ投影式へ通す。
6. 背景を切り抜き・拡大した場合、軍勢にも同じ画面変換を適用する。

現在は元画像の上部84pxと下のUIを除き、縦888pxの範囲を等倍比率で画面いっぱいに拡大する。倍率は1080/888。座標にもこの倍率と切り抜き位置を適用する。背景だけ拡大すると軍勢がずれる。

今回の未使用3地点の最大ずれは、元画面で約1.33px、出力画面で約1.62px。ただしこれは合成上の位置合わせの誤差。陣跡の記念地点が当時の軍勢の中心を正確に示す、という意味ではない。

## 肖像と軍勢の作り方

肖像の登録は `data/portraits.json`、取得は `scripts/fetch_portraits.py`。ファイルの説明ページ・所蔵先・権利表示・元URL・SHA-256を残す。

今回採用したのは、小早川秀秋像、高台寺蔵／石田三成像の模本、東京大学史料編纂所蔵／徳川家康像、大阪城天守閣。Wikimedia Commonsの各ファイルページを出典として記録している。

顔の位置を確認して円形に切り抜く。全体像と顔の拡大は用途が違う。出典を確認できない人物は別人の肖像や生成顔で埋めず、名前の札にする。今回の大谷吉継は名前のみ。

軍勢は `scripts/render_army_sprites.py` で作る。20体を一つの拡大記号として、3色×12姿勢の透過画像を描画する。20体は実際の兵数ではない。脚・腕の関節を動かすが、服装の厳密な考証や地形との完全な3D接触は保証しない。

小早川の肖像は軍勢位置から横280px、縦−25pxを基準に追従し、字幕を避けるため中心の縦位置を720px以下へ制限する。位置が変わっても指示線で同じ部隊へ結び続ける。

## 描画・動画化を速くする

- 音声・背景・軍勢の素材を再利用する。文字の変更のために地形や軍勢モデルを毎回ゼロから描き直さない。
- `scripts/build_earth_film.py` はフレーム範囲を3分割し、別プロセスで合成する。範囲を重複させず、抜けも作らない。
- 動画の断片を結合してから、全体の音声を一度だけ重ねる。音声も分割して再圧縮・連結すると、境界のずれを増やす。
- RTX 4060のNVENCを使い、H.264／yuv420p／AAC／1080p30fpsで出力する。
- 比較時は、解像度・カメラ・尺・進軍をそろえる。同時実行や他アプリの影響がある測定を、厳密な性能差として断定しない。

## 自動検証の順番

```powershell
.venv\Scripts\python.exe scripts/verify_earth.py
.venv\Scripts\python.exe scripts/write_earth_report.py
```

`verify_earth.py` が確認するもの：

- 本編と短編の全フレームをFFmpegでデコード。仕様・尺・フレーム数を確認。
- 音声を実際にデコードし、無音・極端な音量・クリッピングを確認。
- 全フレームの合成時に部隊札の境界と札同士の重なりを検査。字幕も行数・文字幅を検査する。
- 動画から実画像を取り出し、予測された移動先に小早川の肖像があることを画素照合する。
- 必須の地図出典が実動画に残ることと、元の上下の帯が地図で置き換わっていることを画素照合する。
- 肖像の素材ハッシュ、参照元ID、歩行画像の差分、別地点での位置合わせを確認。

現在の本編は6,719フレーム、短編は686フレーム。合成時の全フレーム検査と、動画から取り出す抜き取り画像の検査は区別する。独立ASRによる発音・内容検証、全画面OCR、歴史的意味の検証までは行っていない。

## 失敗から得た対処法

| 症状 | 今回の原因・対処 | 再発時の判断 |
|---|---|---|
| 地形が玩具のように見える | DEMに人工的な色と森林を付けただけだった。実景画像へ変更 | 実測標高であることだけで写実性を主張しない |
| Windowsで日本語ファイルを読めない | 既定の文字コードがcp932。UTF-8を明示 | Pythonはencoding='utf8'、PowerShellからはPYTHONUTF8=1 |
| ブラウザー操作ツールが起動できない | カーネル資産のパスエラー。別のChromium実行で実画面取得 | ツールの失敗とGoogle Earthの利用不能を区別する |
| アクセシビリティ有効化のクリックが失敗 | Flutterの入口が画面外。入口のclickイベントで有効化できた | 実際のUI状態を読んでから次を操作する |
| 肖像の原寸がHTTP429 | 同じCommonsファイルの公開500px版を取得 | 別人の画像で代用しない。利用可能な正当な解像度を選ぶ |
| 地図の一部が粗い・未読み込み | 固定時間の待機だけでは不足 | 読み込み完了と帰属表示を確認して取得し直す |
| 地図を拡大したら位置がずれる | 画像と座標に違う変換を使った | カメラ位置合わせと最終画面変換を分けて管理する |
| 技術PASSなのに完成品に見えない | デコード・座標の検査を作品品質まで広げて解釈した | 技術・史料・表現品質の評価を別々に報告する |

## 別の戦いへ応用するとき

現状は関ヶ原用の固定データと固定カメラを含む。テーマ名を変えるだけで、正しい別作品が自動生成される仕組みではない。

変更するものは、史料と参照箇所、軍勢・陣跡の座標、肖像、背景の範囲、投影の中心、DEM、台本、読み辞書、経路、人物札の配置。特に取得URL、位置合わせの中心、軍勢ID、顔の切り抜き、人物パネルの割当てはスクリプトにも固定値がある。

新しい背景では位置合わせを取り直し、新しい史実の説明には出典を追加する。小早川→大谷の直線を、別の戦いの「実際の進軍路」として流用しない。数値解析も、道路・戦闘・士気を計算していないという前提を引き継ぐ。

## 出典と保管

Googleの映像内帰属、VOICEVOX・音声ライブラリのクレジット条件、各肖像の権利を用途ごとに確認する。概要欄へ書けばすべての映像内表記を消せるとは限らない。今回の確認先は `out/earth_sources.md` と `out/video_description.txt`。

ソース・素材・この手順書はローカルGitで管理している。一方、`out/`、`cache/`、`tools/`、`.venv/`、`node_modules/` はGit対象外。Gitのコミットだけで完成MP4が保管されるわけではない。作品を持ち出す際は、MP4・字幕・概要欄・出典・検証JSONを一緒に保管する。

過去の版を示す場合は、実測値・検査結果をその版の動画ハッシュと合わせる。新しい映像へ古いPASSを流用しない。
