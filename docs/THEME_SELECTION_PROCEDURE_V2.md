# 新・テーマ策定手順（案 v1）

作成：2026-10-16。現行の進め方（`THEME_SELECTION_PROCEDURE.md`）の課題を受けた、**これから使う手順の案**です。使ってみて、足りない所を直します。

## 0. 原則

1. **最終決定はユーザー**。AIは候補と評価を出す。需要の判断と、投稿後の責任がユーザーにあるため。
2. **候補出しは、Claude と ChatGPT が別々に行う**。相手の案を見せずに出し、似た案に引きずられないようにする。
3. **事実を確かめられるかを、必須の関門にする**。確かめられないテーマは、人気が見込めても落とす。
4. **決めた理由と、落とした案の理由を記録する**（`docs/themes/YYYYMMDD_◯◯/` に保存）。

## 1. 流れ

| 段階 | 内容 | 担当 | 成果物 |
|---|---|---|---|
| ①条件の設定 | 長さ、単発かシリーズか、視聴者像、使える素材、避けたい話題を決める | ユーザー（Claudeが質問票を出す） | `01_conditions.md` |
| ②需要の下調べ | YouTubeで、関連語の検索結果・競合の動画（本数、再生数、長さ、コメント）を見る。**AIは実データを持たないので、ユーザーが調べた数字を貼る** | ユーザー | `02_demand.md` |
| ③候補出し | 条件と下調べを渡し、**各AIが別々に10案**。案ごとに、問い（なぜ？）・見せ場・必要な素材・懸念を1〜3行で | Claude／ChatGPT（別々） | `03_candidates_claude.md` `03_candidates_chatgpt.md` |
| ④相互評価 | 相手の案を、下の評価基準で採点する。**自分の案は採点しない** | Claude／ChatGPT | `04_scores.md` |
| ⑤関門の確認 | 上位5案に、事実確認の関門（下記）を実行する | Claude（調査）→ユーザーが確認 | `05_gates.md` |
| ⑥決定 | 上位3案から、ユーザーが選ぶ。却下した案の理由を一行ずつ残す | ユーザー | `06_decision.md` |
| ⑦企画メモ | A4 1枚にまとめる（様式は下記） | Claude | `07_brief.md` |

## 2. 評価基準（各5点、合計25点。関門は別）

| 基準 | 5点の目安 | 1点の目安 |
|---|---|---|
| **見たくなるか** | 「なぜ？」の問いが、タイトルに1行で書ける | 知識の羅列で、問いがない |
| **制作ラインの強み** | 地形・経路・位置関係で確かめられる。諸説を比べられる | 静止画と字幕だけで、新しい見せ方がない |
| **素材と権利** | 肖像・図版・地図が、権利の確かな出どころで揃う | 使える画像がほとんどない |
| **需要** | 検索語があり、競合が弱い（または未飽和） | 需要が見えない、または巨大競合だけ |
| **シリーズへの接続** | 前後の動画に自然につながる | 単発で完結し、広がらない |

## 3. 関門（落とす条件）

次のどれかに当てはまる案は、点数に関係なく落とす。

1. **一次史料または専門書で、骨格の事実を確認できない**（確認できるのが、Wikipedia だけ）。
2. **研究者名つきの主張が、骨格の大半を占める**（原著確認の負担が大きすぎる）。
3. **権利が不明な画像・音源に頼る**。
4. **特定の個人や団体を、不当におとしめる**恐れがある（遺族・現存団体を含む）。
5. **現代の政治・宗教の争点に直結し、公平に扱えない**。

関門の確認結果は、`05_gates.md` に「確認した資料名と、確認日」を書く。

## 4. 候補出しの指示文（Claude・ChatGPT 共通）

```
あなたは、日本史の解説動画（約◯分、ナレーション＋地図・3D地形・肖像）の企画者です。
条件：<01_conditions.md を貼る>
需要の下調べ：<02_demand.md を貼る>
次の形式で、10案を出してください。他のAIの案は見ていません。
1. テーマ名（動画のタイトル案）
2. 問い（視聴者が「なぜ？」と思う1文）
3. 見せ場（地図・地形・資料で何を見せるか。3つまで）
4. 必要な素材と、その権利の見込み
5. 事実確認の見通し（骨格の事実を、どの一次史料・専門書で確かめられるか。分からなければ「不明」と書く）
6. 懸念（炎上・誤情報・権利の恐れ）
知らないことを、あるように書かないでください。研究者名・書名は、確信がなければ書かないでください。
```

## 5. 企画メモ（A4 1枚）の様式

- テーマ名／問い／想定する視聴者／長さ
- 見せ場3つ（地図・地形・資料）
- 構成の骨子（5〜7章、各1行）
- 使う素材と権利（一覧表の場所を書く）
- 事実確認の計画（一次史料・専門書のリスト、確認の担当と期限）
- 懸念と対策
- 次の動画へのつなぎ

## 6. 記録の残し方

```
docs/themes/20261016_<テーマ>/
  01_conditions.md  02_demand.md  03_candidates_*.md
  04_scores.md  05_gates.md  06_decision.md  07_brief.md
```

決定後は、`docs/VIDEO_PRODUCTION_RUNBOOK.md` の「テーマ策定」の節に、うまくいった点・失敗した点を追記する。

## 7. この手順の弱点（先に書いておく）

- **需要の数字は、ユーザーの手作業に頼る**。YouTube の検索データを自動で取れない。
- **AIの採点は、同じ傾向に寄る**。ChatGPT と Claude の採点が似すぎたら、ユーザーが外した案も1つ見る。
- **関門⑤の調査は、私（Claude）が資料にアクセスできる範囲に限られる**。図書館での原著確認は、ユーザーに頼む。
- 使ってみて、段階が重すぎる場合は、②と⑤を簡略化する。
